# یادداشت‌های مهاجرت MySQL → PostgreSQL

## تغییرات
- `mysql2` ← `pg`. اتصال فقط از `DATABASE_URL` (+ `DATABASE_SSL`, `DB_POOL_MAX`). منطق SSL در `src/db.js`.
- همه‌ی SQLها: `?` → `$n`، backtick → `"..."`، `ON DUPLICATE KEY UPDATE` → `ON CONFLICT ... DO UPDATE`، `INSERT IGNORE` → `ON CONFLICT DO NOTHING`،
  `FROM DUAL` حذف، `NOT IN (?)` → `<> ALL($n::text[])`، `IF()` → `CASE`، `tinyint(1)` → `BOOLEAN`.
- `schema.sql` کامل بازنویسی شد (انواع، کلیدهای خارجی، پیش‌فرض‌ها، ایندکس‌ها، ENUM، JSONB، TIMESTAMPTZ، تریگر `updated_at`).
- `init-db.js` و `create-admin.js` برای pg بازنویسی شدند. هیچ مسیر API حذف نشد (فقط `/api/health/db` اضافه شد).

## رفتارهایی که عمداً تغییر کردند
1. ثبت سفارش با کد تخفیف اکنون در یک تراکنش و با یک `UPDATE ... RETURNING` اتمیک انجام می‌شود؛ اگر سفارش ساخته نشود، مصرف کد هم شمرده نمی‌شود (قبلاً شمرده می‌شد و رقابت بین دو خریدار ممکن بود).
2. نام‌کاربری مدیر همچنان به حروف حساس نیست (ایندکس یکتای `lower(username)`).
3. اعداد ورودی گرد و در بازه‌ی ستون محدود می‌شوند (PostgreSQL برخلاف MySQL مقدار اعشاری/خارج از بازه را رد می‌کند). کاراکتر NUL از متن‌ها حذف می‌شود.
4. در production بدون `JWT_SECRET` و `APP_SECRET` سرور بالا نمی‌آید. JWT فقط با HS256 تأیید می‌شود.
5. `create-admin` اگر شناسه‌ی مدیر وجود نداشته باشد خطا می‌دهد (قبلاً بی‌صدا «موفق» چاپ می‌کرد). رمز را می‌توان با `ADMIN_PASSWORD` هم داد.
6. ایندکس روی ستون‌های کلید خارجی اضافه شد (InnoDB خودکار می‌ساخت، PostgreSQL نه). نام ایندکس‌ها یکتا شد (در PostgreSQL سراسری‌اند).
7. `price` و شمارنده‌ها `INTEGER ≥ 0` هستند (سقف ≈ ۲.۱ میلیارد؛ نیمه‌ی بالایی بازه‌ی `INT UNSIGNED` را ندارند).

## محدودیت‌ها
- روی PostgreSQL واقعی اجرا نشده است (محیط ساخت بدون شبکه و بدون PostgreSQL بود). تست‌ها آماده‌اند: `TEST_DATABASE_URL=... npm run test:db`.
- `package-lock.json` ساخته نشد؛ با `npm install` ساخته می‌شود.
- انتقال داده‌های موجود MySQL انجام نشده است.
- مشاهده‌ی قبلی و دست‌نخورده: هویت دانش‌آموز در `/api/public/events` را `userId` سمت کلاینت تعیین می‌کند (احراز هویت ندارد)، و توکن مدیرِ غیرفعال‌شده تا ۱۲ ساعت معتبر می‌ماند.
